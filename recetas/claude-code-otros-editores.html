Claude Code en JetBrains, Visual Studio, Xcode, Zed y Neovim

Qué integración tiene Claude Code en JetBrains, Visual Studio 2022/2026, Xcode, Zed, Cursor y Neovim: quién la mantiene, cómo se instala y qué pierdes.

Probado con Claude Code 2.1.316 · revisado 2026-11-01

Ver los archivos en GitHub Gratis · licencia MIT

Resumen y veredicto

No todo editor tiene «Claude Code» de la misma forma. Hoy (1-nov-2026) hay tres tipos de integración, y conviene saber en cuál estás porque cambian las funciones y la factura:

  • Oficial de Anthropic: VS Code (extensión anthropic.claude-code), Cursor y otros forks de VS Code (la misma extensión, desde Open VSX) y JetBrains (plugin «Claude Code [Beta]» del proveedor anthropic, ID 27310, casi 5 millones de descargas).
  • Del fabricante del editor: Xcode 26.3 (Apple integra «Claude Agent», basado en el Agent SDK, y además expone Xcode por MCP para que la CLI lo use), Zed (Claude Agent instalable desde su registro ACP) y JetBrains AI Assistant 2026.2 (también ofrece un «Claude Agent», distinto del plugin de Anthropic).
  • Sin integración oficial: Visual Studio 2022/2026 (solo extensiones de la comunidad) y Neovim (plugins de la comunidad como coder/claudecode.nvim).

Veredicto: si pagas Claude Pro o Max, quédate en lo que ejecuta la CLI: el plugin oficial en JetBrains, la terminal integrada en Visual Studio o Neovim, y la extensión oficial en VS Code o Cursor. Para todo lo que no está en la lista, la documentación oficial lo dice claro: instala la CLI y ejecuta claude en la terminal integrada del editor. Las funciones completas (skills, hooks, subagentes, modo plan, /rewind) están siempre en la CLI; cuanto más lejos de ella, más hay que comprobar qué falta.

Cómo lo probamos

Esta comparativa se ha hecho solo con documentación oficial, sin instalar nada: cada fila de la tabla lleva al lado la página de Anthropic, Apple, JetBrains, Zed o Microsoft que la respalda. Separamos lo que publica Anthropic, lo que publica el fabricante del editor y lo que es de la comunidad, y no recomendamos ninguna extensión de terceros.

Qué se puede comprobar en Linux (pendiente de hacerlo en una próxima revisión): el plugin de JetBrains en IntelliJ Community o PyCharm con la CLI 2.1.316 (/ide y el visor de diferencias), Zed con Claude Agent desde el ACP Registry, Neovim con :terminal claude, y Cursor o Devin Desktop. Qué no se puede probar en Linux: Xcode (solo macOS) y Visual Studio 2022/2026 (solo Windows); esas filas se basan únicamente en la documentación de Apple y Microsoft citada.

JetBrains (IntelliJ, PyCharm, WebStorm, Android Studio, GoLand, PhpStorm)

El plugin de Anthropic no trae su propia CLI: ejecuta claude en la terminal integrada y se conecta a ella. Por eso hay que instalar las dos cosas: la CLI (si no está en el PATH verás «Cannot launch Claude Code») y el plugin «Claude Code [Beta]» del JetBrains Marketplace; después, reinicia el IDE.

Funciones: abrir con Ctrl+Esc (Cmd+Esc en Mac), diferencias en el visor del IDE, compartir la selección o pestaña actual, insertar referencias con Alt+Ctrl+K (por ejemplo @src/auth.ts#L1-99) y leer los diagnósticos del IDE con la herramienta getDiagnostics. Desde una terminal externa, conecta con /ide. El visor de diferencias se cambia en /config → Diff tool.

claude --version            # el plugin necesita la CLI en el PATH
which claude                 # ruta para «Claude command» si el IDE no la encuentra
claude                       # dentro de la terminal del IDE: integración activa
# desde una terminal externa, ya dentro de Claude Code:
/ide                         # → «Connected to IntelliJ IDEA.»
/config                      # Diff tool: auto (IDE) o terminal

Trampas:

  • Si Esc no interrumpe a Claude, en Settings → Tools → Terminal desmarca «Move focus to the editor with Escape».
  • En Remote Development el plugin va en el host remoto.
  • En WSL2, el aviso «No available IDEs detected» suele ser el cortafuegos.
  • Las reglas Read deny también bloquean que el IDE comparta esos archivos (ver permisos).

Funciona con cualquier plan de pago de Claude o cuenta de Console, sin clave de API.

El otro «Claude Agent» de JetBrains: cuidado con la factura

JetBrains AI Assistant 2026.2 (página del 7-oct-2026) incluye un Claude Agent dentro de su chat, basado en el protocolo ACP. No es el plugin de Anthropic: según la documentación de JetBrains se activa con la suscripción JetBrains AI, con tu clave de API de Anthropic (BYOK) o con una cuenta de Anthropic Console, y «el método elegido se usa para procesar y facturar». La página no menciona los planes Pro o Max de Claude, así que no des por hecho que tu suscripción sirve ahí.

Si ya pagas Claude Pro o Max, la ruta que la documentación de Anthropic garantiza es el plugin oficial + la CLI. En el chat de JetBrains pierdes la terminal de Claude Code, pero ganas integración con el resto del AI Assistant. Nosotros recomendamos el plugin oficial salvo que tu empresa ya pague JetBrains AI.

Visual Studio 2022 y 2026: no hay extensión oficial

Anthropic publica la extensión para VS Code (Visual Studio Marketplace y Open VSX), no para Visual Studio. En la documentación oficial no hay página de Visual Studio, y en las notas de versión de Visual Studio 2026 el agente integrado es el de GitHub Copilot. Dos datos útiles verificados:

  • Visual Studio 2026 descubre skills en .claude/skills/ del repositorio y en ~/.claude/skills/ del perfil (además de .github/skills/ y .agents/skills/), así que tus skills de Claude Code también le sirven a Copilot allí.
  • La ruta oficial para usar Claude Code es abrir la terminal de Visual Studio (Ver → Terminal) en la carpeta de la solución y ejecutar claude. Si aún no la tienes, sigue la receta de instalar Claude Code en Windows.

Existen extensiones de la comunidad que envuelven la CLI (por ejemplo para VS 2017-2026), pero no son de Anthropic: si instalas una, revisa el código, quién la publica y qué permisos pide. No las enlazamos como recomendación.

Xcode 26.3: integración de Apple y conexión por MCP

Desde Xcode 26.3 (requiere macOS Sequoia 15.6 o posterior) Apple integra agentes de Anthropic y OpenAI. Se activa en Xcode → Settings → Intelligence → Agents → «Get» junto al agente y luego «Install»; la cuenta se configura en la fila Account del agente. Anthropic anunció el 3-feb-2026 que es una integración nativa del Claude Agent SDK, el mismo motor de Claude Code, con subagentes, tareas en segundo plano y plugins.

Segunda vía, para quien prefiere la CLI: activa «Allow external agents to use Xcode tools» en la sección Model Context Protocol y añade Xcode como servidor MCP (más sobre MCP en MCP para programadores):

# 1) Xcode → Settings → Intelligence → Model Context Protocol → «Allow external agents to use Xcode tools»
# 2) En Terminal:
claude mcp add --transport stdio xcode -- xcrun mcpbridge
claude mcp list
# 3) Abre el proyecto en Xcode y luego trabaja con `claude` en la carpeta del proyecto

Problemas conocidos según Apple:

  • Si deniegas el acceso a un proyecto en Escritorio, Descargas o Documentos, no vuelve a preguntar: actívalo en Privacidad → Archivos y carpetas o mueve el proyecto.
  • Las skills invocadas con /skill pueden rechazarse: pídelas por su nombre («usa la skill X»).

Zed, Cursor, Windsurf (Devin Desktop) y Neovim

Zed integra Claude como «External Agent» por el Agent Client Protocol. Se instala Claude Agent desde el ACP Registry y se abre un hilo en el Agent Panel. Según la documentación de Zed, Claude Agent tiene su propia autenticación y facturación (una clave de Anthropic configurada para Zed Agent no le sirve), se elige con /login en el hilo y puede leer CLAUDE.md directamente; los servidores MCP de Zed pueden reenviarse por ACP.

Cursor: la documentación de Anthropic tiene un enlace de instalación directo para Cursor de la misma extensión. Después del incidente del 29-30 de octubre (copia con puerta trasera en Open VSX, versiones 2.1.312 y 2.1.313, ya retiradas), comprueba publicador y versión: lo explica nuestra receta de Claude Code en VS Code.

Windsurf, renombrado Devin Desktop en junio según la prensa: la documentación de Anthropic cita «Devin Desktop» entre los forks donde se instala la extensión desde Open VSX.

Neovim: no hay plugin oficial. Usa la CLI en :terminal (Claude Code tiene modo vim en /config → Editor mode) o un plugin de la comunidad como coder/claudecode.nvim (más de 3.100 estrellas), revisándolo antes.

# Visual Studio: Ver → Terminal, en la carpeta de la solución
claude
# Neovim: abre una terminal dentro del editor
:terminal claude
# Cursor / forks de VS Code: comprobar publicador y versión en la ficha de la extensión (Extensiones → Claude Code).
# En VS Code el equivalente por terminal es (no verificado con el comando de Cursor):
code --list-extensions --show-versions | grep -i claude

El modo vim para el prompt de Claude Code, en ~/.claude/settings.json:

{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}

Qué pierdes fuera de la CLI y cómo comprobarlo

La documentación de plataformas lo resume: la CLI es la superficie más completa; el scripting y el Agent SDK son solo de la CLI, y las extensiones cambian algunas funciones por una revisión visual. Regla práctica:

  • Si tu editor ejecuta la CLI (plugin de JetBrains, terminal de Visual Studio, Neovim), tienes todo Claude Code porque es el mismo programa.
  • Si el editor usa su propio agente (JetBrains AI, Xcode, Zed), tus CLAUDE.md, skills y MCP pueden leerse o no según el agente, y la facturación puede ser otra.

Para comprobar qué ha cargado, abre una sesión y escribe /context (archivos de memoria y skills), /status (cuenta y modelo) y /mcp. Si algo no aparece, la receta de errores comunes y /doctor son el siguiente paso. Configuración, memoria del proyecto y servidores MCP se comparten entre las superficies locales de Anthropic, así que puedes alternar terminal y editor en el mismo repositorio. Si aún no tienes un CLAUDE.md, créalo con el generador de CLAUDE.md.

Preguntas frecuentes

¿Hay extensión oficial de Claude Code para Visual Studio 2022?

No. Anthropic publica la extensión para VS Code (y forks), no para Visual Studio. La ruta oficial es ejecutar claude en la terminal de Visual Studio. Las extensiones que encuentres para VS 2022 son de la comunidad.

¿El plugin de JetBrains es gratis?

El plugin se instala gratis desde el Marketplace, pero Claude Code necesita un plan de pago de Claude (Pro, Max, Ultra, Team o Enterprise) o una cuenta de Console, igual que en la terminal.

¿Funciona en Android Studio?

Sí: la documentación oficial incluye Android Studio entre los IDE de JetBrains compatibles con el plugin.

¿Puedo usar mi Claude Pro o Max en el Claude Agent de Xcode, Zed o JetBrains AI?

Depende del fabricante y no lo garantizamos. JetBrains AI documenta su suscripción, clave de API o Anthropic Console (no menciona Pro/Max); Zed dice que Claude Agent tiene su propia autenticación y se elige con /login; Apple solo indica que inicies sesión en la fila Account. Con Pro/Max, lo seguro es la CLI o el plugin oficial.

¿Mis skills y CLAUDE.md funcionan en esos editores?

En la CLI y el plugin de JetBrains, sí (es el mismo programa). Zed indica que Claude Agent puede leer CLAUDE.md; Visual Studio 2026 descubre skills en .claude/skills; en Xcode, Apple avisa de que invocar skills con /skill puede fallar y recomienda pedirlas por su nombre.

¿Es seguro instalar Claude Code en Cursor?

Sí, si es la extensión del publicador Anthropic y una versión limpia. El 29-30 de octubre de 2026 Open VSX sirvió versiones manipuladas (2.1.312 y 2.1.313, ya retiradas). Revisa el publicador y la versión como explica la receta de VS Code.
