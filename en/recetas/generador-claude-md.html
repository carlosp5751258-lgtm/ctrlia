    What's included
    

    The tool is above: you fill in your project's name, stack, commands, rules and gotchas, and it generates a CLAUDE.md, an AGENTS.md or both (a shared AGENTS.md + a CLAUDE.md that imports it with @AGENTS.md). As you type, it checks for what the official documentation advises against, and at the end you download the files. It works offline, without sign-up and without sending anything: everything happens in your browser. The generated text is in Spanish; the English version in the repository's en/ folder generates it in English.
    

    The code (a single JavaScript file with no dependencies, an example index.html and its Node tests) is in the free repository ctrlia-generador-claude-md.
    

    What it generates and why with those rules
    

    The official documentation says Claude treats CLAUDE.md as context, not as mandatory configuration, and gives three rules the tool applies: concrete, verifiable instructions ("use 2 spaces", "run npm test before committing"), fewer than 200 lines per file and nothing contradictory. That is why the form does not ask for the folder tree or the dependency list (Claude reads them from the code), and does ask for what you cannot see: how to check the work, hidden conventions, paths it must not touch and known gotchas. The output is organized in sections with headings and bullets, as the documentation recommends.
    

    It fits with the CLAUDE.md that works recipe: the recipe explains the why and the levels (user, project, local, path rules); the generator produces the project file.
    

    Form fields
    

    • Project: name (required, max. 80 characters), stack and a one-sentence description.
    • Commands, copied exactly as you run them: install, dev server, all tests (highly recommended), a single test, lint, types and build. Empty ones are left out.
    • Rules, one per line: how to consider something done (if left empty and there is a test command, it is filled with "Pasa <test> sin errores", i.e. passes the tests without errors), conventions you cannot see in the code (accepts @docs/estilo.md imports), paths it must not touch without asking, known gotchas, branches, commit style and reply language (default "español").
    • Output: CLAUDE.md only, AGENTS.md only or both; a "Claude Code only" field (for example "use plan mode in src/pagos/") that goes only into CLAUDE.md; and a "I also use a CLAUDE.local.md" checkbox to warn about its effect on AGENTS.md.
    

    AGENTS.md logic (verified in the documentation)
    

    Since 2.1.277, with the default value of /config → Project instructions (claude-md-or-agents-md), Claude Code reads AGENTS.md only if there is no CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md in the working directory or above it; ~/.claude/CLAUDE.md and .claude/rules/ do not count. If both exist, CLAUDE.md wins.
    

    That is why the "both" option generates a CLAUDE.md whose first line is @AGENTS.md, followed by a "Claude Code" section with the specific bits: it is the official "Share one file with other coding tools" pattern, it does not read AGENTS.md twice and it also works in sessions where direct reading is not available. We do not suggest the symlink ln -s AGENTS.md CLAUDE.md by default: the documentation warns that on Windows Git turns it into a one-line text file and that the Edit and Write tools do not write through the link. Inside AGENTS.md, Claude Code expands @imports, but other tools may not, and the tool warns you about it.
    

    Checks
    

    Errors (they block the download):
    

    • The project name is missing.
    • The text contains something shaped like a secret (sk-ant-…, 20+ character sk- keys, GitHub ghp_/gho_ tokens, AWS AKIA keys, private key headers or "password/token/secret: value"), because the file gets committed to git.
    

    Warnings (they do not block):
    

    • No test command.
    • Vague rules ("buen código", "código limpio", "buenas prácticas", "best practices", "formatea bien"…).
    • Prohibitions with "nunca/jamás/prohibido" (never/forbidden), which according to the recipe should go into permissions or hooks so they are always enforced.
    • An @import in quotes (the documentation says it is not imported) or with spaces not written as \ .
    • More than 200 lines in any file.
    • @imports inside AGENTS.md.
    • With "both" and the CLAUDE.local.md checkbox, a reminder that this file blocks the direct reading of AGENTS.md.
    

    Backticks in commands are stripped so they do not break the formatting. The preview uses textContent, so nothing you type is interpreted as HTML.
    

    Privacy and accessibility
    

    The page has no inline scripts and no external origins: a single script served from ctrlia.dev, with no fetch, no storage and no analytics of its own. The download uses a Blob and a temporary link with the download attribute, revoked after one second; there is no server receiving the text. Every field has its label, groups are in a fieldset with a legend, the warning list has aria-live="polite" for screen readers and the preview is keyboard-focusable. The logic (generate and validate) is separate from the interface so it can be tested with Node.
    

    How to use it
    

    1. Fill in what Claude cannot see in the code
    

    Start with the command for all tests and for a single test: it is the most useful part of the file. Then the conventions that cannot be deduced from the code, the paths it must not touch without asking and the known gotchas. Leave out the folder tree and the dependencies.
    

    2. Choose the output
    

    If you only use Claude Code, "CLAUDE.md only". If the repository is also used by Codex, Cursor or other agents, "AGENTS.md + CLAUDE.md that imports it", and put what is Claude-only in the "Claude Code only" field.
    

    3. Fix the warnings and download
    

    Errors block the download; warnings do not, but read them: a vague rule is useless and a no-exceptions prohibition works better in permissions or in a hook. Download the file and save it at the root of the repository.
    

    4. Check that Claude Code loads it
    

    Open Claude Code in that folder and run /context: CLAUDE.md should appear under Memory files (if you only use AGENTS.md you will see the line "no CLAUDE.md found; AGENTS.md loaded: …"). Ask a question that depends on the file, for example "how do I run a single test?", and check that it answers with your command.
    

    /context
/doctor prompt-audit
    

    /doctor prompt-audit (2.1.283 or later) makes Claude look for contradictory instructions or ones that point to files that do not exist.
    

    5. Keep it short
    

    Over time, add only what you have already had to correct twice, move long procedures into skills (the your first skill recipe) and prohibitions into permissions or hooks. If your file grows past 200 lines, split it by path with .claude/rules/. And if you also want to review your settings.json, use the settings checker.

    FAQ
    

    CLAUDE.md or AGENTS.md?
    

    If you only use Claude Code, CLAUDE.md. If the repository is also used by Codex, Cursor or other agents, a shared AGENTS.md and a CLAUDE.md with @AGENTS.md for the Claude-specific bits. Since 2.1.277 Claude Code reads AGENTS.md only when there is no CLAUDE.md.
    

    Is my information sent anywhere?
    

    No. The file is generated in your browser by a script from ctrlia.dev and downloaded directly; the page makes no requests with what you type.
    

    How many lines should it have?
    

    The official documentation recommends fewer than 200 per file; the tool warns you if you go over. Whatever only matters in one folder goes into path rules in .claude/rules/.
    

    Why does it warn me about "nunca" (never) in a rule?
    

    Because CLAUDE.md is context, not a guarantee. Anything without exceptions (do not read .env, do not push --force) is always enforced with permission deny rules or a hook.
    

    Can I use a symlink instead of @AGENTS.md?
    

    It works if nobody uses Windows; the documentation warns that Git on Windows turns it into a one-line file and that Claude does not edit through the link. The @AGENTS.md import has none of those problems.
    

    I have a CLAUDE.local.md and Claude no longer reads my AGENTS.md. Why?
    

    That is the documented behavior: CLAUDE.local.md counts as a CLAUDE.md. Put @AGENTS.md in a CLAUDE.md or change /config → Project instructions to claude-md-and-agents-md.
